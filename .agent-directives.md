# Workspace Directives: Token-Constrained Autonomous Agent & Antigravity Rules

Sinkronisasi aturan eksekusi token-hemat, anti-loop, dan arsitektur Minecraft Story (Paper 26.2).

## 1. Core Directives: Token-Constrained Autonomous Agent

### A. Anti-Loop Regulation (Maksimal 2x Percobaan)
1. **Permission / Privilege Errors**:
   - Jika perintah shell/skrip gagal akibat error akses (`Access Denied`, `Execution Policy`, `Administrator privileges required`, dsb.), **DILARANG bypass otomatis**.
   - Hentikan eksekusi saat itu juga. Cetak error asli dan minta user menjalankan secara manual atau berikan izin.
2. **Consecutive Failure Limit**:
   - Jika suatu perintah/skrip gagal **2 kali berturut-turut** dengan error yang sama/mirip: **HALT seketika**. Jangan coba ke-3 kalinya. Laporkan kendala ke user.

### B. Compact Code Deliveries (Minimal Diff / Non-Redundant)
1. Dilarang mencetak ulang blok kode utuh yang tidak mengalami perubahan.
2. Hanya kirim blok kode yang dimodifikasi, ditambah, atau dihapus.
3. Gunakan diff presisi, anchor line marker, atau fungsi edit terarah.

### C. No Chitchat & Maximum Brevity
1. Lewatkan salam pembuka (*"Sure, I can help"*, *"Here is the fix..."*) dan obrolan sopan santun.
2. Langsung ke kode blok, path file, atau perintah.
3. Keterangan teknis ditulis sebagai komentar 1 baris di dalam kode, atau teks penjelasan di bawah 10 kata.

### D. Reuse Memory (Zero Restatement)
1. Dilarang mengulang kembali output kode dari giliran sebelumnya.
2. Referensikan baris/fungsi yang dimaksud dan hanya berikan micro-patch atau penyesuaian yang diperlukan.

## 3. Analisis & Integrasi Obsidian: Apakah Perlu?

### Jawaban Ringkas:
**Perlu dan sangat efektif** untuk konteks modular jangka panjang, **TETAPI** bukan sebagai aplikasi GUI yang berjalan bersama agent, melainkan sebagai **Markdown Vault Terstruktur** (Knowledge Base file lokal `.md`).

### Kenapa Obsidian Hemat Token?
1. **Mencegah Context Bloat**:
   - Daripada memasukkan riwayat obrolan puluhan ribu baris ke prompt (yang membakar ribuan token setiap giliran), informasi dipecah menjadi file atomic Markdown terindeks.
2. **Targeted Read (On-Demand Retrieval)**:
   - Agent hanya membaca file `.md` spesifik yang relevan dengan tugas aktif (misal hanya membaca `coords.md` atau `npc_dialog.md`).
3. **Persistent Checkpoint**:
   - State progress disimpan permanen di file vault, sehingga sesi baru tidak perlu re-explorasi kode dari nol.

## 4. Cara Penggunaan Obsidian / Markdown Vault di OpenCode / Antigravity

Struktur dan alur kerja paling efisien tanpa memboroskan token:

### A. Struktur Folder Vault (Rekomendasi di Project)
```text
project-mc/
└── docs/ (atau vault/)
    ├── index.md           # Indeks utama & peta navigasi
    ├── hud-registry.md    # Definisi koordinat & layer
    ├── quests.md          # State & daftar quest aktif
    └── session-state.md   # Status handover sesi terakhir
```

### B. Protokol Pembacaan Hemat Token
1. **Aturan 1 - Jangan Grep/Read Sembarangan**:
   - Agent dilarang membaca semua file `.md` sekaligus.
   - Baca `index.md` terlebih dahulu untuk melihat pointer.
2. **Aturan 2 - Gunakan Slice / Targeted Offset**:
   - Gunakan fungsi `read` dengan parameter `offset` dan `limit` (misal 50–100 baris saja) untuk mengambil section yang relevan.
3. **Aturan 3 - Catat State Langsung**:
   - Setiap kali task besar selesai, agent langsung menulis ringkasan status ke `session-state.md` dalam format tabel atau bullet pendek (maksimal 30 baris).

### C. Alur Kerja OpenCode Sesi Baru
1. User mulai sesi baru:
   ```text
   Lanjutkan task dari docs/session-state.md. Gunakan aturan .agent-directives.md.
   ```
2. Agent langsung membaca `session-state.md` (hanya makan ~200 token), tahu persis state terakhir, dan langsung bekerja tanpa looping eksplorasi.
